# SD Tasks - 任务文档管理

## 目的
管理规范驱动开发(SD)的 `tasks.md` 文档。基于规格文档(spec.md)和设计文档(design.md)生成逐步实现任务清单，将"构建什么"和"如何构建"转化为可执行的开发步骤。

## 前置条件
项目目录结构：
```
.sd/
└── specs/
    └── {{feature-name}}/
        ├── spec.md      ← 必须存在
        ├── design.md    ← 必须存在
        └── tasks.md
```

**重要：** `.sd/specs/{{feature-name}}/spec.md` 和 `.sd/specs/{{feature-name}}/design.md` 必须都存在，才能生成 `tasks.md`。

## 触发条件
- 用户请求生成实现任务（如："生成任务"、"generate tasks"、"sd tasks"）
- sd-design 成功完成后
- 用户想查看或修改已有的 tasks.md

## 核心能力

### 1. 创建任务文件
按以下步骤生成新的 `tasks.md` 文件：

1. **验证前置条件：** 确认 `spec.md` 和 `design.md` 都存在
2. **若任一缺失：** 提示用户先完成缺失的文档，并告知所需skill

### 第1步：理解特性需求
- 读取 `.sd/specs/{{feature-name}}/spec.md` 获取项目背景和特性列表
- 读取 `.sd/specs/{{feature-name}}/design.md` 获取代码设计方案
- 在上下文中理解特性需求的完整范围

### 第2步：生成实现任务
- 默认使用中文（除非用户另有要求）
- 将所有需求映射到任务
- 确保所有设计组件被包含在任务中
- 验证任务递进逻辑合理且增量式
- 每个任务应具有明确的描述和验收条件
- 任务顺序应遵循：基础设施 → 核心逻辑 → 接口 → 集成 → 测试

### 第3步：保存任务
- 若 `.sd/specs/{{feature-name}}/tasks.md` 不存在，创建它
- 保存路径：`.sd/specs/{{feature-name}}/tasks.md`

### 2. 更新任务文件
- 任务修改仅写入 `.sd/specs/{{feature-name}}/tasks.md`
- 当 spec.md 或 design.md 变更时，提示用户是否需要重新生成 tasks.md
- 支持增量更新（添加/删除/修改单个任务）

### 3. 读取任务文件
- 使用 `Read` 加载完整任务内容
- 使用 `Grep` 搜索特定任务或关键词
- 支持按状态筛选任务（待办、进行中、已完成）

## 任务生成原则

### 任务结构
每个任务应包含：
- **任务编号：** 递增编号（T1, T2, T3...）
- **任务标题：** 简明描述（不超过30字）
- **任务描述：** 详细说明实现内容
- **依赖任务：** 前置任务编号（无依赖则标注"无"）
- **涉及文件：** 需要创建或修改的文件路径
- **验收条件：** 任务完成的可验证条件

### 任务排序原则
1. **基础设施优先：** 项目配置、依赖安装、目录结构
2. **数据模型次之：** 实体类、数据模型、数据库迁移
3. **核心逻辑：** 业务规则实现、核心算法
4. **接口层：** API端点、控制器、路由
5. **集成层：** 外部服务集成、中间件配置
6. **测试验证：** 单元测试、集成测试、端到端测试

### 质量检查
- 每个spec需求至少对应一个任务
- 每个设计组件至少对应一个任务
- 无孤立任务（所有任务都有明确来源）
- 任务间依赖关系无循环

## 执行指南
1. 生成前必须验证 spec.md 和 design.md 都存在
2. 默认语言：中文
3. 任务粒度适中：不过粗（一个任务包含太多内容），不过细（拆分到单行代码级别）
4. 保持与 spec 和 design 的可追溯性
5. 生成后建议用户审阅任务顺序和粒度

## 示例输出
```markdown
# 实现任务清单

## T1: 项目基础配置
- **描述：** 初始化项目结构，安装必要依赖
- **依赖：** 无
- **涉及文件：** package.json, tsconfig.json
- **验收条件：** 项目可成功编译运行

## T2: 数据模型定义
- **描述：** 根据设计文档定义核心数据模型
- **依赖：** T1
- **涉及文件：** src/models/*.ts
- **验收条件：** 所有模型类型定义完整，通过类型检查
```

## 下一步
tasks.md 完成后，按任务顺序逐个实现代码，所有任务完成后执行 `sd-verify` 验证代码与设计的一致性。
