# SD Init - 规范驱动开发目录初始化

## 目的
创建规范驱动开发(SD)的目录结构，为需求规格、技术设计和实现任务跟踪建立整洁的工作空间。从用户的自然语言需求描述中生成一致的特性标识符和目录布局。

## 触发条件
- 用户开始新特性开发并希望使用SD工作流
- 用户明确请求初始化SD目录（如："init sd"、"sd init"、"初始化规范驱动开发"）
- 首次交互开始SD驱动的特性开发时
- 如果 `.sd/specs/{feature-name}/` 已存在同名特性，则不得使用

## 核心工作流

### 第1步：基础目录验证与创建
验证核心规格目录（`.sd/specs/`）是否存在：
- 若目录不存在：创建 `.sd/` 和 `.sd/specs/`
- 若目录已存在：列出现有特性目录供参考
- `.sd/` 目录作为所有SD产物的根目录

### 第2步：特性名称生成
从用户需求描述中生成简洁的 `feature_name` 标识符：

**严格约束：**
- 最大长度：10个字符
- 允许字符：小写英文字母(a-z)、数字(0-9)、下划线(_)
- 不允许空格、大写字母、特殊字符或符号
- 必须具有描述性，来源于需求

**生成规则：**
1. 从需求描述中提取关键名词/动词
2. 使用下划线作为分隔符组合
3. 若超过10个字符则截断（优先保留最关键的词）
4. 验证与已有特性目录的唯一性

**有效示例：** `user_login`、`data_sync`、`api_v3`、`pwd_reset`
**无效示例：** `userLogin`、`data sync`、`api-v3`、`password_reset_feature`

### 第3步：特性目录创建
构建完整目录路径：`.sd/specs/{feature_name}/`

创建占位结构：
```
.sd/
└── specs/
    └── {feature_name}/
        └── .gitkeep
```

### 第4步：输出摘要
向用户报告初始化结果：
- 生成的特性名称
- 创建的目录路径
- 下一步指引（建议运行 sd-spec 创建 spec.md）

## 示例执行
**用户输入：** "实现用户账户的安全密码重置功能"

**第1步：** 确认 `.sd/specs/` 存在（不存在则创建）
**第2步：** 生成 `feature_name`：`pwd_reset`
**第3步：** 创建目录：`.sd/specs/pwd_reset/`
**结果：** 目录 `.sd/specs/pwd_reset/` 已就绪，可进行SD文档编写

## 错误处理
- 特性名称无法生成（输入模糊）：请用户提供明确的特性名称
- 目录已存在：警告用户，建议使用现有目录或提供替代名称
- 文件系统权限拒绝创建：报告错误，建议手动创建
