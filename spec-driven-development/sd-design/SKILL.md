# SD Design - 设计文档管理

## 目的
管理规范驱动开发(SD)的 `design.md` 文档。确保设计文档的一致创建、更新和检索，将"构建什么"(Spec)转化为"如何构建"(Design)，同时保持清晰的关注点分离。

## 前置条件
项目目录结构：
```
.sd/
└── specs/
    └── {{feature-name}}/
        ├── spec.md    ← 应存在（提供需求上下文）
        └── design.md
```
`.sd/specs/{{feature-name}}/` 目录必须存在。**建议**在创建 `design.md` 前 `spec.md` 已存在，以确保设计与需求对齐。

## 触发条件
- 用户请求创建/编写/更新设计文档
- 用户说"写设计"、"创建设计文档"、"write design"、"create design"
- sd-spec 成功完成后
- 用户想查看或修改已有的 design.md

## 核心能力

### 1. 创建设计文件
按以下步骤生成新的 `design.md` 文件：

1. **验证目录：** 检查 `.sd/specs/{{feature-name}}/` 是否存在
2. **检查存在性：** 检查该目录下是否已有 `design.md`
3. **读取规格上下文：** 若 `spec.md` 存在，先读取以理解需求再进行设计
4. **生成内容：** 结合用户需求 + 规格上下文 + `design_template.md` 结构生成 design.md
5. **严格格式：** design.md 格式必须严格遵循 `design_template.md` 结构
6. **填充章节：** 包含模板中的所有必需章节，按用户需求和规格要求填充内容
7. **禁止覆盖：** 若 design.md 已存在，告知用户并建议使用更新操作

### 2. 更新设计文件
更新已有 `design.md` 文件的规则：

1. **目标文件：** 所有修改仅写入 `.sd/specs/{{feature-name}}/design.md`
2. **保持结构：** 更新时维持模板章节结构
3. **全文重写：** 用户提供编辑内容时，清空并重写整个 design.md
4. **增量更新：** 用户请求特定章节更新时，仅修改该章节，保留其他章节
5. **规格对齐检查：** 更新后验证设计是否仍覆盖所有规格需求

### 3. 读取与搜索设计文件
- **特性设计：** `.sd/specs/{{feature-name}}/design.md`
- 使用 `Grep` 搜索特定设计元素、接口或模式
- 使用 `Read` 加载完整设计内容以供审查或修改
- 以结构化格式返回搜索/读取结果
- 通过 `Glob` 支持列出所有特性设计文件

## 关键约束：设计定义"如何构建"

### 要求内容（设计范围）
- 实现模型和架构模式
- 服务/组件架构和交互关系
- 接口设计（API契约、数据契约）
- 数据模型（模式、存储策略、索引）
- 技术栈决策及其理由
- 错误处理策略和重试策略
- 缓存、消息传递和基础设施决策
- 部署和扩展考量

### 禁止内容（规格范围）
不得在 design.md 文件中包含以下任何内容：
1. 业务规则和验证逻辑（属于 spec.md）
2. 用户场景和验收条件（属于 spec.md）
3. DFX约束定义（属于 spec.md）
4. 领域术语定义（属于 spec.md）
5. 角色定义（属于 spec.md）
6. 任何回答"构建什么"而非"如何构建"的内容

## 注意事项
聚焦**架构和方案**，不是逐行代码实现！
- 描述组件、其职责和交互关系
- 在设计层面定义接口和契约
- 指定数据模型及其关系
- 记录技术选择及其理由
- 不要在 design.md 中编写实际实现代码

## 执行指南
1. 创建/更新前始终验证文件路径（使用 `Glob` 确认目录结构）
2. 先读取 spec.md 确保设计覆盖所有需求
3. 在所有设计文件中保持模板格式
4. 破坏性操作前提示用户确认
5. 默认语言：中文（除非用户另有要求）
6. 确保每个设计决策可追溯到规格需求

## 模板参考
design_template.md 定义以下必需章节：

1. **实现模型**
   - 1.1 上下文视图
   - 1.2 服务/组件总体架构
   - 1.3 实现设计文档
2. **接口设计**
   - 2.1 总体设计
   - 2.2 接口清单
4. **数据模型**
   - 4.1 设计目标
   - 4.2 模型实现

详见 `templates/design_template.md`。

## 下一步
design.md 完成后，建议运行 `sd-tasks` 生成实现任务，编码完成后运行 `sd-verify` 验证代码与设计的一致性。
